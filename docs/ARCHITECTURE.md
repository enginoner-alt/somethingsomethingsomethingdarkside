# Architecture

Self-hosted meeting recorder: any device + any mic → your server → WhisperX
(transcription, word timestamps, pyannote diarization) → per-user storage →
local LLM (OpenAI-compatible API) → insights.

Guiding rule: **no unnecessary complexity.** Every component below must earn
its place in the POC. Anything else goes in "Later".

## Decisions log

| # | Topic | Decision |
|---|-------|----------|
| D1 | Clients | Browser only (PWA-ish). No app stores. Wrap later only if needed. |
| D2 | Connectivity | Online recording. Browser keeps only un-acked chunks in memory; server holds the real copy. |
| D3 | Live transcript | No. Processing after recording ends. |
| D4 | Diarization | Whole recording in one pass (WhisperX + pyannote). No LLM speaker matching. Speakers anonymous; user can rename. |
| D5 | Languages (speech) | Auto-detect by default; per-recording override (e.g. `en`, `tr`). |
| D6 | Languages (UI) | English + Turkish, one JSON file per language in `locales/`. Adding a language = adding a file. |
| D7 | LLM | Local, OpenAI-compatible endpoint(s), configured in admin panel. Multiple endpoints supported, each assigned to a purpose. |
| D8 | GPU sharing | Admin toggle "LLM shares GPU with WhisperX". When on: worker unloads models after each job and transcription/LLM jobs never overlap. Default: off (assume separate). |
| D9 | Auth | Local accounts (POC) → OIDC (M4). AD + MFA/SSO handled by an IdP (Keycloak/Authentik with AD federation); the app only speaks OIDC. A local break-glass admin always exists. |
| D10 | TLS | Caddy reverse proxy with the user-provided wildcard cert mounted as files. |
| D11 | Sharing | None in-app. Users can download their own data (audio, transcript, insights). |
| D12 | Admin visibility | Admin panel manages settings/users/quotas, never shows other users' content. |
| D13 | Organisation | No user-filled metadata. Title/tags/meeting type are generated by the LLM as part of insights; user may edit them. |
| D14 | Insights | On demand only. Prompt templates: global (admin) + personal (user). |
| D15 | Transcript edits | Allowed. Insights are never regenerated automatically. On edit, user is prompted; a cheap check (local diff size → small LLM call on the diff only) says whether the change is material before spending tokens on a full regeneration. |
| D16 | Reprocessing | Single "re-transcribe" action with language/model override (cheap: pipeline exists; useful when language detection is wrong on mixed EN/TR). |
| D17 | Retention | Kept until user deletes. Delete → trash for 30 days → hard delete (audio, transcript, insights, embeddings). |
| D18 | Privacy (KVKK/GDPR-light) | Configurable consent notice shown before recording starts; working hard delete; "download all my data". No audit log, no app-level encryption at rest (use disk encryption). |
| D19 | Concurrency | 1 GPU job at a time (POC). Queue handles the rest. |
| D20 | Deployment | Docker Compose on one machine (the 4060 laptop for POC). Worker can later run on another machine pointing at the same DB/storage. No Kubernetes. |
| D21 | Mic | Any input `getUserMedia` exposes. Reference POC mic: **ReSpeaker XVF3800** (USB, on-device beamforming/AEC/NS). |
| D22 | Channels / DoA | Transcribe a single channel. Browser uploads what it gets (mono or stereo, untouched); server picks the channel at ffmpeg conversion (`left` / `right` / `mix`, admin default, per-recording override on re-transcribe). No DoA: not in the audio stream, not reachable from a browser, laggy, and pyannote diarizes by voice. |

## Components

```
Browser
  getUserMedia({deviceId, echoCancellation:false, noiseSuppression:false, autoGainControl:false})
  MediaRecorder(timeslice ≈10s) → PUT chunk n  (retry until ack)
  Wake Lock (keeps screen on), pause/resume
        │ HTTPS (Caddy, wildcard cert)
        ▼
api  (FastAPI, Jinja2 + htmx + small vanilla JS recorder)
  auth, recordings, chunk receiver, transcript/insight/export endpoints, admin panel
        │
        ▼
Postgres  (data + job queue via SELECT … FOR UPDATE SKIP LOCKED — no Redis)
        │
        ▼
worker  (CUDA image, WhisperX + pyannote)        llm-worker (same codebase, no GPU)
  ffmpeg → 16 kHz mono WAV                          calls OpenAI-compatible endpoint
  transcribe → align → diarize                      templates, map-reduce for long text,
  segments + words + speaker embeddings → DB        title/tags/meeting type, change-check
        │
        ▼
/data volume: audio/{user_id}/{recording_id}/  (chunks → original.{webm|mp4} after finalize)
```

### Recording / upload protocol

1. `POST /api/recordings` → `{id}` (consent notice acknowledged client-side first).
2. `PUT /api/recordings/{id}/chunks/{seq}` — idempotent; same seq twice is a no-op.
3. `POST /api/recordings/{id}/finalize {last_seq}` — server checks contiguity,
   concatenates in order (only chunk 0 has the container header, so order matters),
   validates with ffprobe, enqueues transcription.
4. Uploaded existing files (`POST /api/recordings/upload`) skip steps 2–3.

Browser DSP (echo cancellation / noise suppression / AGC) is **off by default**
so devices like the XVF3800 aren't double-processed; user toggle to turn it on
for cheap laptop mics.

### Mic notes (XVF3800)

- Class-compliant USB audio → shows up in `enumerateDevices()` on Windows,
  Linux, Android, and iOS (USB-C / adapter). Device label needs mic permission first.
- It can expose more than one processed channel depending on firmware (e.g. a
  "conference" beam with heavy NS vs. an "ASR" beam with lighter processing).
  Browsers may downmix. Per D22 the channel is chosen server-side; M1/M2 record
  one meeting, transcribe each channel, and set the better one as default.
- DoA is not used (D22).

### Data model (core tables)

`users`, `recordings` (status, language, duration, deleted_at), `chunks`,
`jobs` (type, status, attempts, payload), `segments` (start, end, speaker, text,
edited), `words`, `speakers` (recording-local label, display name, embedding),
`templates` (owner null = global), `insights` (recording, template, output,
transcript_version), `llm_endpoints` (url, model, key, purpose), `settings`
(key/value for admin panel).

### Admin panel settings

Whisper model, compute type, batch size, default language, diarization on/off,
min/max speakers hint, max recording length, LLM endpoints + purposes, context
size per endpoint, GPU-sharing toggle, per-user quotas (storage, max recording
length, jobs/day), global templates, consent notice text, user management.

### Exports

Per recording: audio (original), Markdown, TXT, SRT, VTT, JSON. Per user:
"download all my data" zip.

## Known constraints / risks

- **iOS / Android:** recording stops if the tab is backgrounded or the screen
  locks. Mitigation: Wake Lock + "keep tab in front" UI. Real fix (later, only if
  needed): native wrapper.
- **8 GB VRAM:** large-v3 + pyannote fit sequentially; exact compute type /
  batch size tuned in M2. Models load per job; unload when GPU sharing is on.
- **Mixed EN/TR in one meeting:** Whisper picks one language per file.
  Mitigation: manual language override + re-transcribe.
- **Pyannote models are gated:** each deployment needs a Hugging Face token that
  accepted the model terms. Models cached in a volume after first download.
- **Mic access needs HTTPS** — handled by Caddy + wildcard cert, even on LAN.

## Later (explicitly out of POC)

Cross-recording search / Q&A (pgvector), voiceprint-based speaker suggestions
across recordings, multiple GPU workers, DOCX export, native wrapper, in-app sharing.
